# Bluebell provisioning bundle

Generated by tools/gen-schema.mjs — do not hand-edit; re-run the tool.

Bluebell keeps JMIS's `bluebell_*` table names verbatim (brand.json `renameTables=false`)
and runs in its **own** Supabase project, so there is no rename step and no shared-
database hazard. Regenerate after any JMIS schema change:

    node tools/gen-schema.mjs

Paste into **Bluebell's** Supabase SQL Editor (project `BLUEBELL_SUPABASE_REF_PLACEHOLDER`) in this order,
one file at a time — or paste `apply_all.sql` on its own:

| order | file | what it does |
|---|---|---|
| 1 | `01_schema.sql` | `CREATE TABLE IF NOT EXISTS` for 31 tables, exact JMIS columns/types, PKs, deferred FKs |
| 2 | `02_rls.sql` | enables RLS + permissive `anon`/`authenticated` policies |
| 3 | `00_indexes.sql` | indexes/policies authored in `bluebellschool/src/api/*.sql`, replayed through `bb_try()`; needs the tables from step 1, so it is pasted after them |
| 4 | `03_storage.sql` | public buckets (cbt, images, passport, setting, staff_passport) + storage policies |
| 5 | `04_seed_bluebell.sql` | the single `bluebell_settings` row + first admin grant |

`bb_try()` reports and skips a statement that does not apply instead of aborting the
batch, so one bad statement cannot block the rest - but that also means pasting
`00_indexes.sql` before the tables exist would quietly create no indexes at all.
With a Supabase personal access token the same order is applied automatically:
`node tools/run-sql.mjs --apply`.

Nothing in the bundle is destructive: every statement is `IF NOT EXISTS`,
`DROP POLICY IF EXISTS`-guarded or `NOT VALID`-deferred, so the whole set can be
re-pasted after a change.

## Placeholders

Bluebell's real school values are unknown at clone time and are emitted as
`BLUEBELL_*_PLACEHOLDER`. Fill them in `tools/site-content.json` (settings +
contact/about copy) and re-run this generator, or edit the `bluebell_settings` row through
the admin Setting page afterwards. Run `grep -rn "BLUEBELL_.*PLACEHOLDER" db` to
list whatever remains.

## Upgrading to byte-exact DDL

The catalog carries columns, types, nullability, primary keys and foreign keys,
but **not** defaults, indexes or hand-written policies. `tools/export-exact-ddl.sql`
is a read-only query to run in the **JMIS** editor that prints the exact
`CREATE TABLE`/`pg_get_indexdef`/`pg_constraint`/`pg_policies` text for the same
table set; paste the result into `db/01_schema_exact.sql` if you ever need the
generated bundle replaced with the literal JMIS definition.
